# 0.5.0 验证范围

验证环境：Windows 11 x64、Electron 45、TeX Live 2025、XeLaTeX。

## 自动测试

```powershell
npm test
npm run test:integration
npm run build
```

24 项单元测试覆盖源码保留、事务与冲突检查、连续文稿转换、字数统计、查找匹配和替换边界。4 项真实 LaTeX 编译测试覆盖图片宽度、源码定位、错误恢复、文字格式、分页、图片与跨页表格，以及公式单独重建。

GitHub Actions 执行单元测试和构建。需要本地字体与 TeX Live 的编译测试独立运行。

## 桌面程序检查

已在 Windows 目录版程序中检查以下流程：

- Ctrl+F / Ctrl+H 打开共用查找替换面板，前后导航、Esc 关闭、区分大小写和字面匹配。
- 写作视图跨格式替换、表格正文替换、公式边界保持、全部替换后撤销与重做。
- 源码按当前文件查找，替换前的在途输入单独保存为事务；切换视图、保存和重新打开保持内容一致。
- 字体颜色、图片插入和缩放、表格编辑、选区字数、独立公式重建及正式 PDF 更新。
- 1100 × 800 窗口中的工具区无溢出；教程标题与 Windows 程序图标为蓝色。

独立 PDF 检查覆盖中文字体嵌入、字号、图片嵌入、长文稿分页、跨页表格内容完整和撤销后的页面一致性。

## 性能观测

在一份 23592 字符、150 段、22 页的受控文稿中，目录版连续输入 144 次，其中 97 次发生在后台排版期间。由 `beforeinput` 到第二个 `requestAnimationFrame` 回调的时间为：中位数 17.9 ms、P95 19.2 ms、最大 20.2 ms；未观测到超过 50 ms 的主线程任务。

写作和源码视图不创建隐藏 PDF 画布；字数和文档标题按文档状态缓存，避免光标移动时重复序列化全文。这些数字属于单机受控观测，不代表所有硬件和文稿的性能。

## 尚未覆盖

真实 Windows 中文输入法候选窗、复杂出版社模板、长期使用和更多硬件环境仍需要进一步验证。已有 Chromium 组合输入检查，不能替代真实系统输入法测试。浏览器写作排版和最终 PDF 可能存在断行差异。
